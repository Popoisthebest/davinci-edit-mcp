# v0.4 테스트 프로젝트 전용 편집

실제 Resolve API를 호출하는 기본 편집 경로를 구현했습니다. 자동 테스트는 모의 Resolve를 사용하며, Windows 11 + Resolve 21.1.1.10 Free에서의 실행은 아직 미검증입니다. 설치된 API나 LuaJIT FFI가 없으면 중단하며 Studio 기능으로 우회하지 않습니다. 실제 영상 편집 성공이나 렌더 완료를 주장하지 않습니다.

## 구현 범위와 보호 경계

- 기본 MCP 시작은 v0.3 조회 도구 9개뿐입니다. `--enable-writes`와 만료되는 로컬 승인이 모두 있어야 편집 도구 9개가 추가됩니다. MCP 도구로 승인 파일을 만들거나 권한을 확대할 수 없습니다.
- 승인은 정확한 `ResolveMCP_TEST_<name>` 신규 프로젝트명, 새 전용 테스트 미디어 폴더, 세션, 유효 시간에 묶여 HMAC 서명됩니다. 기본 30분, 최대 60분이며 취소할 수 있습니다.
- 모든 프로젝트를 닫아야 새 프로젝트를 생성합니다. 기존 이름의 프로젝트를 열거나 재사용하지 않습니다. 브리지가 생성한 프로젝트 ID, 현재 프로젝트명·ID, 승인 ID를 매번 검사하며, 다른 프로젝트로 바뀌면 거부합니다. Lua 재시작 후 기존 프로젝트를 채택하지 않습니다.
- `ResolveMCP_TEST_BIN_` bin 생성, 복사한 테스트 미디어 1개씩 가져오기, 1080×1920/30fps/frame 0 타임라인 생성, 자체 생성 타임라인 복제, 비디오·스테레오 오디오 트랙 추가, 프레임 단위 클립 배치와 읽기 검증, 테스트 프로젝트 명시적 저장을 지원합니다.
- 원본 경로, 외부 폴더, 링크·junction, 하드링크는 가져오기 대상에서 거부합니다. 테스트 미디어는 직접 복사한 파일이어야 합니다. 코드에서 원본 미디어를 수정하거나 삭제하지 않습니다. Windows 전용 폴더에는 현재 사용자/SYSTEM ACL을 적용합니다.
- 타임라인/미디어/bin ID는 이 브리지 세션에서 생성한 것만 사용합니다. 사용자 기존 프로젝트, `팩트체크_쇼츠_템플릿`, `쇼츠_기본_타임라인`, 원본 `D:\팩트체크스튜디오\02_원본자료`, 게임·캐시·백업을 편집 경로에 전달하지 않습니다.
- 삭제, 컷, 원본 덮어쓰기, 프로젝트 재사용, 렌더링 및 임의 코드 실행 도구는 없습니다. 실행 중 Resolve UI에서 프로젝트/타임라인을 수동 전환하지 마세요. API 호출과 수동 UI 조작 전체를 원자적으로 잠글 수는 없습니다.

## 프레임 규칙

`source_in`, `source_out`은 반열린 구간 `[in,out)`입니다. 예를 들어 3–4는 정확히 1프레임이며 Resolve에는 `startFrame=3,endFrame=3`을 전달합니다. `record_frame`은 타임라인의 절대 프레임, `track_index`는 1부터 시작합니다. `media_type=1`은 비디오, `2`는 오디오입니다.

현재는 FPS=30 및 유효한 Frames 속성을 반환하는 미디어만 배치합니다. 29.97/VFR·리타이밍·프레임 정보 없는 음원·스틸의 길이 변환은 지원하지 않습니다. 30fps 비디오의 오디오 트랙 선택 경로는 모의로 검사했으나 WAV/MP3 파일의 실제 프레임 해석은 미검증입니다. 정확한 소스 범위, 타임라인 해상도/FPS, 존재하는 트랙과 겹침을 먼저 확인합니다. 배치 후 반환 객체와 대상 트랙에서 시작/끝 프레임 및 미디어 ID를 읽고, GetLeftOffset/GetRightOffset으로 소스 in/out도 확인합니다.

`resolve_plan_append`는 Resolve를 변경하거나 타임라인을 활성화하지 않는 사전 검사입니다. `resolve_append_clip`은 검사를 다시 한 뒤 실제 API를 호출합니다. 실패·타임아웃·검증 불일치 시 자동 재시도하거나 자동 삭제하지 않습니다. 이미 일부 변경됐을 수 있으므로 `resolve_timeline_items`로 확인하고, 필요하면 전용 테스트 프로젝트에서 수동 정리하세요. 원본 프로젝트를 복구 대상으로 삼지 않습니다.

## Windows 로컬 승인과 실행

설치·업그레이드·롤백은 [v0.3 지침](v0.3.md)의 새 전용 경로를 사용합니다. 기존 설치와 프로젝트/원본을 먼저 백업하고 Resolve를 닫은 뒤 `scripts/Install.ps1`을 실행하세요. 설치 스크립트는 활성 manifest·전용 launcher를 백업하며 기존 v0.2를 덮어쓰지 않습니다. 세션을 교체하면 기존 승인과 테스트 미디어 marker도 무효화됩니다.

```powershell
$app = Join-Path $env:LOCALAPPDATA 'ResolveMCPNext'
$python = (Get-Content -Raw (Join-Path $app 'active.json') | ConvertFrom-Json).python
$media = Join-Path $env:LOCALAPPDATA 'ResolveMCP_TEST_MEDIA_v04_demo'

# 반드시 존재하지 않는 새 폴더를 지정합니다. 원본 폴더를 지정하지 않습니다.
& $python -m resolve_mcp.server --prepare-media-root $media
# 사용자가 복사한, 폐기 가능한 30fps fixture.mp4를 위 폴더에 넣습니다.

# 정확한 신규 프로젝트명을 로컬에서 재입력하여 승인합니다.
& $python -m resolve_mcp.server --approve-test-project `
  --project-name ResolveMCP_TEST_v04_demo `
  --confirm-project-name ResolveMCP_TEST_v04_demo `
  --media-root $media --approval-minutes 30

# Resolve를 실행하고 모든 기존 프로젝트를 닫은 뒤,
# Workspace > Scripts > Utility > ResolveMCPNext를 한 번 실행합니다.
# 클라이언트용 stdio 프로세스(이 옵션이 없으면 조회 도구만 등록됩니다)
powershell.exe -NoProfile -File .\scripts\Start.ps1 -EnableWrites

# 중단: 이후 요청을 차단합니다. 이미 진행 중인 API 호출은 취소할 수 없습니다.
& $python -m resolve_mcp.server --revoke-approval
powershell.exe -NoProfile -File .\scripts\Start.ps1 -StopBridge
```

편집 순서는 신규 프로젝트 생성 → bin 생성 → 테스트 미디어 import → 타임라인 생성 → 사전 검사 → 클립 배치 → 읽기 확인 → 명시적 저장입니다. 기존 프로젝트를 닫지 않았다면 첫 단계가 거부됩니다. 승인되지 않은 기존 타임라인을 복제하는 기능은 없습니다. 새 테스트 프로젝트 자체가 원본과 분리된 작업본입니다.

전송한 편집 요청과 완료/오류는 전용 mailbox의 `audit.jsonl`에 기록합니다. 키·미디어 경로·원본 데이터는 기록하지 않습니다. 로그가 1MiB를 넘으면 로컬에서 보관한 후 정리하기 전까지 새 편집을 막습니다. 실패 로그의 TIMEOUT은 실행 여부가 불확실하다는 뜻입니다. 브리지 재시작 후에는 새 이름의 신규 테스트 프로젝트를 다시 승인해야 하며 기존 테스트 프로젝트의 정리·보관은 사용자 UI에서 수행합니다.

## 검사 상태

```bash
python -m pip install -e '.[test]'
python -m unittest discover -s tests -v
```

LuaJIT의 실제 핸들러·서명·파서를 실행하고 MCP stdio를 통해 새 프로젝트 생성부터 배치·조회·저장까지 왕복 검사합니다. Resolve API와 미디어 내용은 모의입니다. 승인 부재/위조/만료/취소, 프로젝트 전환, 외부/링크 파일, FPS·프레임·트랙 범위, 겹침, 실패 응답, 배치 readback 불일치, 동일 요청 중복 실행 방지를 검사합니다.

Windows 커널 파일·뮤텍스 검사와 Resolve 조회/편집 실기기 검사는 기본 스킵이며 통과로 계산하지 않습니다. 실제 편집 검사는 로컬 승인과 복사한 `fixture.mp4`, 닫힌 기존 프로젝트, 실행 중인 새 Lua 브리지를 준비한 후 Windows에서 `RESOLVE_MCP_EDIT_INTEGRATION=1`을 명시해야 합니다. 전용 새 테스트 프로젝트를 생성·편집·저장하고 보존하며, 자동 삭제하지 않습니다. 실기기 검증 전 기능별 Free API 호환성·Unicode 설치 경로·설치/업그레이드/롤백 성공은 미검증입니다.

2026-10-18 Linux 재검사: 전체 90개 중 81개 PASS, Windows 커널 검사 7개와 Resolve 조회/편집 실기기 검사 2개 SKIP, 실패 0개입니다. PowerShell 구문 분석과 Windows 커널 테스트의 이번 작업 실행 결과는 GitHub Actions에서 별도로 확인합니다. 설치·업그레이드·롤백의 실제 Windows 실행과 실제 Resolve API 검증을 대체하지 않습니다.

이 버전의 변경 파일은 `editing.py`, `permissions.py`, Lua `edits.lua`, 기존 통신/시작·MCP 등록 코드, `Start.ps1`, 편집 테스트·실기기 opt-in 검사 및 이 문서입니다. v0.2 파일은 변경하지 않았습니다. 릴리스 되돌리기는 Resolve를 닫은 뒤 `scripts/Rollback.ps1`을 사용하며, 진행 중 API 호출이나 테스트 프로젝트 내부 편집을 자동으로 되돌리는 기능은 없습니다.

## ChatGPT Desktop 공식 규격 확인

2026-10-18 공식 [Desktop-only plugin 문서](https://developers.openai.com/plugins/deploy/desktop-only)를 확인했습니다. 문서는 로컬 stdio MCP를 사용하는 Desktop-only plugin 구조와 로컬 실행 스레드를 설명하며, 제출은 승인된 파트너/조직 allowlist가 필요하다고 명시합니다. 현재 저장소에는 해당 plugin 배포 패키지나 실제 ChatGPT Desktop 연결 검증이 없습니다. [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)과 공개 Streamable HTTP 배포 경로도 별도이며 이 로컬 브리지를 공용 네트워크에 노출하지 않습니다. 이 작업의 확인 범위는 MCP stdio 및 모의 Resolve 동작입니다.

## 편집 보호·읽기 검증 보완

Python과 Lua 양쪽에서 세션에 묶인 테스트 미디어 marker를 검증합니다. Lua도 파일 확장자·전용 루트·하드링크를 검사하여 서명된 RPC라도 이 조건을 우회할 수 없습니다. 배치 사전 검사에서 가져온 미디어 ID·원래 가져온 경로를 다시 대조하고, 다른 파일로 relink되거나 삭제된 타임라인은 활성화 전에 거부합니다. 타임라인 시작 프레임 0과 정수인 소스 전체 프레임 수를 재확인합니다.

배치 API의 반환 객체와 별도로 대상 트랙을 다시 읽고 미디어 ID·시작/끝 프레임·좌우 소스 offset이 정확히 일치하는 항목이 하나인지 확인합니다. 잘못된 미디어·소스·중복 결과나 일부 변경 후 API 실패는 오류로 보고하고 자동 삭제·재시도를 하지 않습니다. `resolve_timeline_items`의 미디어 ID·offset을 이용해 상태를 확인할 수 있습니다. 지연된 쓰기가 타임아웃 이후 완료된 경우도 별도 요청으로 조회하며 감사 로그에는 TIMEOUT을 유지합니다.

opt-in 실제 Resolve 검사는 신규 프로젝트에서 import, 세로 30fps 타임라인 생성, 비디오 트랙 추가, 1프레임 trim 배치·조회, 타임라인 복제, 저장까지 검사하도록 확장했습니다. 이 환경에는 사용자 Windows PC와 Resolve가 없으므로 이 경로는 실행하지 않았습니다. 일반 음원·VFR·자막·렌더링은 지원/완료 주장에 포함하지 않으며 삭제·컷 도구도 노출하지 않습니다.

추가 변경 파일은 `editing.py`, `bridge/edits.lua`, `tests/edit_support.py`, `tests/test_editing.py`, `tests/test_resolve_integration.py`와 본 문서입니다. v0.3 전송·조회 수정도 포함합니다. 릴리스 되돌리기는 `Rollback.ps1`의 별도 설치본 백업 복구를 사용합니다. 테스트 프로젝트 내부 편집의 자동 undo는 제공하지 않으며 원본 프로젝트를 복구 대상으로 사용하지 않습니다.

Windows CI에서 발견한 기존 파일 교체·일시적 공유 잠금 문제의 수정과 실제 핸들 회귀 검사는 v0.3 전송 계층에 반영한 뒤 이 버전에도 포함했습니다. 파일 읽기만 제한적으로 다시 시도하며 편집 API는 자동 재실행하지 않습니다. 최신 CI 증거는 PR 검사 탭 및 PR 본문에 기록합니다.

추가 Windows 전용 검사에서는 실제 Win32 canonical 경로·한글 파일/폴더의 식별, 하드링크 및 링크된 상위 폴더의 거부를 확인합니다. 파일과 폴더의 타입 혼동도 거부합니다. 이 검사는 Resolve API 검증과 분리됩니다.

## require/package가 없는 Resolve 호스트

Console에 전역 ffi/bit가 제공되는 사용자 결과를 반영해 내부 Lua 모듈을 고정 factory registry로 묶었습니다. canonical 경로 검사의 숨은 bit require도 제거했으며 HMAC·승인·프로젝트 소유권·미디어/경로 보호는 유지합니다. Console/Utility의 사용 가능한 전역은 다를 수 있으므로 각각의 진단이 필요합니다.

먼저 [Windows 조회 전용 실기기 진단](windows-readonly-probe.md)을 실행합니다. v0.4 진단도 편집 dispatcher를 생성하거나 승인 파일을 읽지 않습니다. 편집 모듈은 정의만 로드해 의존성을 검사합니다. 이 진단의 두 실기기 결과를 확인하고 사용자가 다음 단계를 승인하기 전까지 실제 클립 편집 검사는 보류합니다. 기존 자동 편집 테스트는 모의 Resolve 회귀 검사이며 실기기 실행과 구분합니다.
