# v0.3 설치·검증 기록

v0.2는 보존하고 새 Python 패키지와 Lua 브리지를 분리했습니다. 기본값은 읽기 전용이며 외부 HTTP 포트, 임의 Lua/Python 실행, 프로젝트 전환/저장 도구는 없습니다.

## 변경 내용

- `ping`, 현재 프로젝트/타임라인을 유지하고 프로젝트 목록, 타임라인 목록, 트랙, 미디어 풀, 렌더 출력 설정, 타임라인 클립 배치 조회를 추가했습니다. 프로젝트 목록은 현재 데이터베이스 폴더 범위입니다.
- 요청·응답을 평문 데이터와 HMAC-SHA256으로 처리합니다. 공유 키는 소유자 전용 mailbox에 보관하며 로그/응답으로 공개하지 않습니다. 요청 ID, 브리지 인스턴스, 만료 시간, 크기/개수 제한을 검증합니다. 인증 실패는 실행 없이 무시합니다.
- 동일 ID/내용은 만료 전 캐시 응답을 반환합니다. 같은 ID의 다른 내용은 거부합니다. Python은 스레드 및 OS 파일 잠금으로 서버 프로세스 사이도 직렬화합니다. Lua는 Windows 명명 뮤텍스로 중복 실행을 거부합니다. 세션 교체 시 기존 브리지는 종료합니다.
- 타임아웃/실패 시 자동 재시도하지 않습니다. 특히 향후 쓰기 작업은 타임아웃 후 실행 여부가 불명확할 수 있으므로 먼저 조회해야 합니다.
- Fusion.prefs를 읽거나 쓰지 않습니다. 새 mailbox 파일만 사용합니다. Lua `io=nil` 환경을 고려해 LuaJIT FFI의 Win32 Unicode 파일 API를 사용합니다. FFI/bit/debug 또는 필요한 Resolve API가 없으면 명확하게 중단합니다. 요청을 `loadfile`로 실행하는 대체 경로는 없습니다.

## Windows 설치·업그레이드·복구

실기기에서는 아직 실행하지 않았습니다. Windows 11, Python 3.12, Resolve 21.1.1 Free가 목표입니다. 원래 설치본과 원본 프로젝트/미디어를 먼저 백업하고 Resolve를 완전히 종료하세요.

```powershell
powershell.exe -NoProfile -File .\scripts\Install.ps1
# Resolve 실행 후 Workspace > Scripts > Utility > ResolveMCPNext 한 번 실행
powershell.exe -NoProfile -File .\scripts\Start.ps1 -SelfTest
# 로컬 stdio MCP 클라이언트의 시작 명령
powershell.exe -NoProfile -File C:\path\davinci-edit-mcp\scripts\Start.ps1
# 명시적으로 브리지를 종료하거나 세션을 교체할 때
powershell.exe -NoProfile -File .\scripts\Start.ps1 -StopBridge
powershell.exe -NoProfile -File .\scripts\Start.ps1 -RotateSession
# Resolve를 닫고 설치 출력의 backup ID로 복구
powershell.exe -NoProfile -File .\scripts\Rollback.ps1 -BackupId YYYYMMDD-HHMMSS-1234abcd
```

설치는 `%LOCALAPPDATA%\ResolveMCPNext`에 새 릴리스를 만들고, 사용자/SYSTEM 전용 ACL을 적용합니다. 새 Utility 메뉴 진입점 `ResolveMCPNext.lua`만 등록합니다. 기존 `ResolveMCP.lua`, v0.2 서버, Fusion.prefs, 프로젝트 라이브러리, 미디어, 캐시는 변경하지 않습니다. 매 설치·업그레이드 및 롤백 전에 활성 manifest/전용 launcher를 백업합니다. 설치 실패 시 기존 활성 파일을 유지하거나 복구하며, 롤백 시 릴리스와 mailbox 파일은 보존합니다.

## 자동 테스트와 실기기 검사

```bash
python -m pip install -e '.[test]'
python -m unittest discover -s tests -v
```

자동 검사는 실제 LuaJIT에서 새 Lua 프로토콜과 조회 핸들러를 실행하지만 Resolve 객체는 모의입니다. v0.2 Python 응답 회귀, HMAC 벡터/변조, 요청 재생/만료, 동시 프로세스, stale 응답, 재시작/정지, 경로·권한 및 실제 MCP stdio를 검사합니다. Lupa 2.8은 테스트 전용 MIT 라이선스 의존성입니다. 외부 GitHub 구현 코드를 복사하지 않았습니다.

Windows CI 정의는 추가했으나 여기서 GitHub Actions 결과나 Windows 설치 성공을 주장하지 않습니다. 실기기 조회 검사는 기본 스킵이며 Windows에서 `RESOLVE_MCP_INTEGRATION=1`을 명시한 뒤 실행합니다. 셸 설치/업그레이드/롤백, Unicode 경로, FFI 제공 여부, 실제 Free API 결과는 미검증입니다. 디스크를 조작할 수 있는 같은 사용자/관리자 악성 프로세스는 보호 경계 밖입니다. ACL·HMAC은 다른 계정과 잘못된/변조된 요청에 대한 방어이며, 로컬 계정이 침해된 환경의 보안을 보장하지 않습니다.

## 공식 문서 확인 상태

- Secure MCP Tunnel: https://developers.openai.com/api/docs/guides/secure-mcp-tunnels (별도 연결 방식, 미구현)

렌더링·영상 편집·자막·ChatGPT Desktop 연결은 v0.3 완료 주장에 포함하지 않습니다.

## Windows CI에서 발견한 공유 핸들 수정

첫 Windows Actions 실행에서 응답 파일을 읽는 Python CRT 핸들이 파일 교체를 막아 `WinError 5`와 연쇄 타임아웃이 발생했습니다. Python 읽기를 Win32 `FILE_SHARE_READ|WRITE|DELETE` 핸들로 교체했고, 세션 키 읽기도 크기를 제한했습니다. 읽는 중 파일 교체를 검증하는 Windows 전용 테스트를 추가했으며 모의 브리지도 동일한 읽기 방식을 사용합니다. mailbox 초기화는 설치 스크립트 사용 여부와 관계없이 현재 사용자/SYSTEM 전용 ACL을 적용합니다.

Linux 재검사: 43개 중 39개 PASS, Windows 커널 3개·실제 Resolve 1개 SKIP, 실패 0개. GitHub Actions 수정 후 결과는 PR 검사 탭에서 별도로 확인합니다. CI Windows 성공도 Resolve 21.1.1.10 Free의 실제 API 검증과 구분합니다.

공유 DELETE 읽기만으로는 Windows `MoveFileEx`의 기존 대상 교체가 해결되지 않아 Python/Lua 모두 기존 파일에는 `ReplaceFileW`를 사용하고 최초 발행에만 이동을 사용하도록 수정했습니다. 읽기 핸들을 유지한 채 Python/Lua 양쪽 writer로 교체하는 회귀 검사로 확인합니다. [Microsoft ReplaceFileW 공식 문서](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)의 공유 모드·ACL 규칙을 따릅니다. 파일 게시 실패 시 명령을 자동 재전송하지 않습니다.
